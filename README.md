# نظام مكتب الأستاذ مصطفى حمزة

تطبيق Next.js متصل بـ Supabase (قاعدة بيانات + مصادقة) وجاهز للنشر على Vercel.

## خطوات النشر بالترتيب

### 1) إنشاء مشروع Supabase
1. روح على https://supabase.com وسجّل / سجّل دخول.
2. أنشئ مشروع جديد (New Project) واختار كلمة مرور لقاعدة البيانات واحفظها.
3. من `Project Settings > API` هتلاقي:
   - `Project URL` → هو `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public key` → هو `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role key` → هو `SUPABASE_SERVICE_ROLE_KEY` (سري جدًا، لا تشاركه)

### 2) تشغيل السكيما (الجداول + الصلاحيات)
1. من Supabase Dashboard افتح `SQL Editor`.
2. افتح ملف `supabase/schema.sql` من هذا المشروع، انسخ كل المحتوى، الصقه في SQL Editor، واضغط Run.
   - ده هيعمل الجداول كلها (clients, invoices, expenses, tasks, activity_log, declaration_status, settings, profiles) ويفعّل الحماية (Row Level Security) حسب الأدوار.
3. بنفس الطريقة، شغّل ملف `supabase/indexes.sql` كمان (لتسريع الاستعلامات).

### 3) تجهيز المشروع محليًا
```bash
npm install
cp .env.local.example .env.local
```
افتح `.env.local` واملأ فيه القيم الثلاث اللي جبتها من خطوة (1).

### 4) إنشاء المستخدمين الثمانية
```bash
npm run seed-users
```
ده هينشئ حسابات الدخول الثمانية (مصطفى، محمد، يمنى، منار، ندى، نوران، مريم، متدرب) بكلمات مرور مبدئية موجودة داخل `scripts/seed-users.js`.
**غيّر كلمات المرور فورًا** من Supabase Dashboard > Authentication > Users > اختار المستخدم > Reset password، أو عدّل الكلمات في السكريبت قبل تشغيله.

### 5) تجربة التطبيق محليًا (اختياري لكن مستحسن)
```bash
npm run dev
```
افتح http://localhost:3000 وجرّب تسجيل الدخول بأي حساب.

### 6) رفع المشروع على GitHub
```bash
git init
git add .
git commit -m "أول نسخة من نظام المكتب"
```
أنشئ مستودع جديد فاضي على GitHub وارفع الكود عليه (`git remote add origin ...` ثم `git push`).

### 7) النشر على Vercel
1. روح على https://vercel.com وسجّل دخول (يفضّل بحساب GitHub).
2. اضغط "Add New Project" واختار المستودع اللي رفعته.
3. في خطوة الإعدادات (Environment Variables) ضيف:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **لا تضيف** `SUPABASE_SERVICE_ROLE_KEY` هنا — هو مطلوب محليًا بس لسكريبت seed-users.
4. اضغط Deploy، واستنى دقيقة لحد ما ياخد لينك زي `your-project.vercel.app`.

بكده الموقع شغال أونلاين ومتصل بقاعدة بيانات حقيقية، وأي حد من الثمانية يقدر يدخل من أي جهاز.

## تحديثات مهمة (بعد أول نسخة)

### 1) السرعة
- كانت الصفحة بتعمل بعض الاستعلامات بالتتابع بدل ما تعملهم مع بعض؛ اتصلحت في `lib/useOfficeData.js` وبقت كل الاستعلامات بتتنفذ في نفس الوقت (Promise.allSettled) — تحسّن ملموس في سرعة أول تحميل.
- شغّل الملف الجديد `supabase/indexes.sql` في SQL Editor (نفس طريقة `schema.sql`) — ده بيضيف فهارس على الأعمدة اللي بتتفلتر وتترتب كتير (التواريخ، ربط العميل، المهام) وبيسرّع الاستعلامات مع زيادة عدد الصفوف.
- لو السرعة لسه بطيئة بعد الخطوتين دول: تأكد إن **منطقة (Region) مشروع Supabase** قريبة من منطقة **Vercel** (عادة Vercel بيختار أقرب منطقة تلقائيًا، لكن Supabase بتختاره وقت إنشاء المشروع) — لو الاتنين في قارات مختلفة، في تأخير شبكة طبيعي مش حل برمجي ليه، غيّر منطقة المشروع لو أمكن.

### 2) نموذج استيراد العملاء
النموذج الفارغ بقى ملف Excel حقيقي مُجهّز مسبقًا (`public/client-import-template.xlsx`) بدل ما يتولّد من الموقع، وفيه:
- قوائم منسدلة حقيقية شغالة في Excel لعمود (نوع المنشأة) و(ق.م) — تضغط على الخلية ويظهرلك سهم تختار منه.
- تنسيق احترافي (رأس الجدول بلون كحلي، حدود، أعمدة بعرض مناسب، صف العناوين مثبّت فوق).
- ورقة تانية اسمها "تعليمات" فيها شرح مختصر لطريقة التعبئة.

### 3) مشكلة "invalid input syntax for type date"
كانت بتحصل لأن Excel بيخزن التواريخ كرقم تسلسلي داخليًا (زي 46233)، والاستيراد كان بياخده زي ما هو من غير تحويل. اتصلحت المشكلة في دالة الاستيراد (`app/(app)/clients/page.js`) عن طريق قراءة الملف بخاصية `cellDates: true` وتمرير كل تاريخ على دالة تحويل جديدة `excelToISODate()` في `lib/helpers.js` بتفهم الأرقام التسلسلية وكمان صيغة نصية زي DD/MM/YYYY وتحوّلها لصيغة تفهمها قاعدة البيانات.

### 4) عرض كل التواريخ بصيغة DD/MM/YYYY
اتعدّلت دالة `fmtDate()` في `lib/helpers.js` عشان ترجع دايمًا يوم/شهر/سنة بغض النظر عن لغة أو إعدادات المتصفح — وده بيظهر في كل الجداول والتقارير وملفات التصدير.

**ملاحظة صغيرة:** خانات إدخال التاريخ في نماذج الإضافة/التعديل (زي "تاريخ التسجيل") بتستخدم عنصر تاريخ قياسي من المتصفح نفسه (`<input type="date">`)، وشكل عرضه جوه الصندوق نفسه بيتحكم فيه نظام التشغيل/المتصفح مش الموقع — لكن أي مكان تاني في الموقع (الجداول، التقارير، ملفات Excel المصدّرة) هيظهر دايمًا DD/MM/YYYY كما طلبت.

### 5) الإقرارات: البداية من يناير 2026 + عرض الشهر الحالي فقط
- الإقرارات بقت بتتولد ابتداءً من يناير 2026 فقط (مش من السنة اللي قبلها) — الإعداد موجود في `lib/helpers.js` باسم `DECLARATIONS_START_YEAR`، لو حبيت تغيّره لسنة تانية غيّره من هناك.
- صفحة الإقرارات ولوحة التحكم بقوا بيعرضوا بس الإقرارات **المستحقة في الشهر الحالي** (سواء لسه متأخرة أو خلصت)، وشيلنا فلتر "الشهر/السنة" اليدوي لأنه بقى مش لازم.
- **تنبيه مهم:** بما إن العرض بقى مقتصر على الشهر الحالي بس، لو فيه إقرار من شهر فات ولسه متأخر ومحدش خلّصه، مش هيظهر في القائمة دلوقتي. لو حابب نضيف تبويب أو فلتر لاحقًا لمتابعة الإقرارات المتأخرة من شهور سابقة كمان، قولّي وأضيفه.

### 6) زرار مسح سجل النشاط
- في صفحة **الإعدادات** بقى فيه زرار "امسح السجل" (متاح للمدير والأدمن بس)، بيمسح كل سجل النشاط القديم ويسجّل سطر واحد جديد يوضح مين مسحه وإمتى.
- **لازم تشغّل SQL إضافي مرة واحدة** عشان الزرار يشتغل: افتح `supabase/add_activity_log_delete_policy.sql`، انسخ محتواه، والصقه في SQL Editor واضغط Run. (لو ده مشروع جديد ولسه هتشغّل `schema.sql` لأول مرة، السطر ده أصلاً متضاف جواه ومحتاجش تعمل الخطوة دي بشكل منفصل.)

### 7) حذف المهام: للأدمن فقط
- زرار حذف ظهر في صفحة **المهام** جنب كل مهمة، لكنه بيظهر ويشتغل **لمحمد (أدمن) بس** — حتى مصطفى (المدير) مش هيقدر يمسح مهام من الواجهة ولا من قاعدة البيانات نفسها.
- **لازم تشغّل SQL إضافي مرة واحدة**: افتح `supabase/add_tasks_delete_policy.sql`، انسخ محتواه، والصقه في SQL Editor واضغط Run. (لو ده مشروع جديد ولسه هتشغّل `schema.sql` لأول مرة، السطر ده أصلاً متضاف جواه.)

### 8) التواريخ الهامة تظهر في بيانات العميل + في ملف الإكسل
- صفحة عرض بيانات العميل بقت بتعرض قسم "تواريخ هامة" فيه كل تاريخ مع عدد الأيام المتبقية أو التأخير.
- ملف التصدير والاستيراد (`public/client-import-template.xlsx`) بقى فيه 3 أعمدة تواريخ إضافية: انتهاء اشتراك موقع الضرائب، انتهاء التوكن، لجان الطعن — بتتزامن تلقائيًا مع نظام التذكيرات.

### 9) إصلاح مهم: المحاسبين ما كانوش شايفين مهامهم
كان فيه خطأ في صلاحيات قاعدة البيانات بيمنع كل محاسب من رؤية المهام المرسلة له أو منه (كانت المقارنة بحقل خطأ). **اتصلح دلوقتي**، وكل محاسب هيشوف بس المهام اللي بينه وبين غيره، والأدمن يشوف كل حاجة.
⚠️ **لازم تشغّل ملف SQL جديد لتفعيل الإصلاح**: افتح `supabase/fix_tasks_visibility_and_notes.sql`، انسخ محتواه كامل، والصقه في SQL Editor واضغط Run. (لو مشروع جديد لسه هيشغل schema.sql، الإصلاح ده متضمن فيه أصلاً.)

### 10) ملاحظة على كل مهمة
تحت كل مهمة بقى فيه زرار "+ إضافة ملاحظة" — أي شخص شايف المهمة (المرسل، المستقبل، أو الأدمن/المدير) يقدر يكتب ملاحظة عليها وتتحفظ فورًا.

### 11) عداد المهام غير المعتمدة في القائمة الجانبية
- **للمدير والأدمن**: الرقم اللي بيظهر جنب "المهام" في القائمة الجانبية بقى يعرض عدد كل المهام اللي لسه ما اتعملهاش اعتماد تنفيذ (مش بس المهام الجديدة).
- **لباقي المستخدمين**: يفضل يعرض عدد المهام الجديدة الموجهة ليهم شخصيًا، زي ما كان.

### 12) الوضع الداكن
كانت بعض النصوص بتفضل سوداء وغير واضحة في الوضع الداكن. اتصلحت المشكلة من مكان مركزي واحد (لون النص الافتراضي لكل الصفحة)، فكل الجداول والنصوص بقت واضحة في الوضعين.

### 13) بيانات المكتب (تليفون / عنوان)
للتوضيح: أنا (Claude) معنديش تليفون أو عنوان المكتب فعليًا — دول حقول فاضية في صفحة **الإعدادات** (تليفون المكتب والعنوان) مُعدّة عشان تملأها انت بنفسك وقتما تحب، ومحدش طلبها مني قبل كده. لو حابب تحطها دلوقتي، روح صفحة الإعدادات واكتبها واحفظ.

### 14) صفحة تسجيل الدخول: تصميم احترافي + النص التعريفي
صفحة الدخول بقى فيها تصميم بشاشة مقسومة: النص التعريفي الكامل بتاع المكتب (هدفنا/رسالتنا/رؤيتنا) في جانب، ونموذج الدخول في الجانب التاني.
- **الشعار**: لسه معملتليش صورة الشعار في المحادثة، فحطيت مكانها حاليًا الحرفين "مح" كبديل مؤقت. لو حبيت تحط الشعار الحقيقي: سمّي ملف الصورة `logo.png` وحطه جوه مجلد `public/` في المشروع (نفس مكان `client-import-template.xlsx`)، وارفعه على GitHub — هيظهر تلقائيًا من غير أي تعديل في الكود.

### 15) فلاتر إضافية في صفحة الفواتير
بقى فيه فلتر "نوع المنشأة" وفلتر "ق.م" في صفحة الفواتير، بيفلتروا الفواتير حسب بيانات العميل المرتبط بيها.

### 16) صافي الربح
اتشال من لوحة التحكم زي ما طلبت (لسه موجود في صفحة التقارير لو حبيت تشوفه هناك).

### 17) المحاسب يشوف مهامه (المرسلة له والمرسلة منه) + عداد الاعتماد
- كل محاسب/متدرب بيشوف تلقائيًا كل المهام اللي بينه وبين أي حد تاني (مرسلة له أو منه) — ده كان شغال من الإصلاح اللي عملناه قبل كده، وأكدنا عليه.
- بقى فيه عداد واضح فوق صفحة المهام نفسها بعنوان "مهام لسه محتاجة اعتماد تنفيذ"، وبرضو رقم العداد في القائمة الجانبية بقى بيعكس نفس الحاجة لكل المستخدمين (مش بس المدير/الأدمن).

### 18) بيانات المكتب في صفحة تسجيل الدخول
لما تملأ "تليفون المكتب" و"العنوان" في صفحة الإعدادات وتحفظ، هيظهروا تلقائيًا وبشكل احترافي (بأيقونات) في صفحة تسجيل الدخول تحت النص التعريفي — من غير ما تحتاج تكتب أي كود.
⚠️ **لازم SQL إضافي**: شغّل `supabase/add_declaration_amount_and_public_settings.sql` عشان تسمح بظهور بيانات المكتب في صفحة الدخول (اللي بتُعرض قبل تسجيل الدخول أصلاً).

### 19) الإقرارات: نطاق أوسع بشهر + تتبع مبالغ كامل
- بقى فيه شهر سماح إضافي — يعني أي إقرار فتح ميعاد تقديمه (حتى لو لسه ما فاتش) بيظهر في القائمة عشان تقدر تعلّم عليه وتسدده أول ما يفتح الميعاد، مش تستنى لحد ما يتأخر.
- رجعنا حالة "قيد الانتظار" تظهر تاني في القائمة (كانت اتشالت قبل كده)، عشان تقدر تشوف وتتعامل مع الإقرار من أول يوم يفتح فيه ميعاد التقديم.
- كل إقرار بقى ليه **قيمة إجمالية** (تكتبها إنت) وحالة سداد: **مدفوع كامل** / **صفري** (مفيش مبلغ مستحق) / **مبلغ جزئي** (تكتب المبلغ المدفوع والباقي بيتحسب لوحده تلقائيًا). دوس على زرار "السداد" جنب أي إقرار عشان تدخلهم.
- بقى فيه كارت جديد فوق اسمه **"مبالغ إقرارات متأخرة"** بيجمع كل المتبقي على كل العملاء المتأخرين في السداد؛ دوس عليه يفتحلك جدول فيه كل عميل عليه فلوس، المبلغ، ونوع/فترة الإقرار.
⚠️ **لازم SQL إضافي** (نفس ملف البند اللي فات): `supabase/add_declaration_amount_and_public_settings.sql` بيضيف عمود "قيمة الإقرار" الجديد لقاعدة البيانات.

### 20) إصلاح جذري نهائي لمشكلة رؤية المهام
اكتشفنا السبب الحقيقي: الصلاحيات كانت بتقارن **نص** اسم الشخص حرف بحرف، ولو الاسم اتكتب بفرق بسيط (مسافة زيادة مثلاً) وقت إنشاء أي حساب يدويًا، الصلاحية كانت بترفض تظهر المهمة. **الحل النهائي**: بقت المقارنة بمُعرّف المستخدم الحقيقي (ID) مش بالاسم النصي — ده مستحيل يغلط تاني مهما اختلفت طريقة كتابة الاسم.
⚠️ **لازم SQL جديد**: شغّل `supabase/fix_tasks_id_based_permissions.sql`. ده بيحاول يربط المهام القديمة تلقائيًا بالمعرف الصحيح (لو الاسم كان متطابق)، لكن أي مهمة قديمة ما اتربطتش صح ممكن تحتاج إعادة إرسال. أي مهمة جديدة من دلوقتي هتتربط صح 100% تلقائيًا.

### 21) الإقرارات: رجّعنا الميعاد الأصلي (من غير شهر زيادة)
كان فيه شهر زيادة زودته غلط في المرة اللي فاتت. اتصلح: إقرار يونيو هيفضل "قيد الانتظار" طول شهر يوليو بالظبط زي ما طلبت، وهكذا لباقي الشهور — من غير تأخير شهر إضافي.

### 22) مبالغ الإقرارات المتأخرة
الكود بيحسب المبلغ المتبقي بناءً على "قيمة الإقرار" اللي بتدخلها من زرار "السداد" جنب كل إقرار. لو الكارت كان شايف 0 قبل كده، السبب غالبًا إن عمود "قيمة الإقرار" في قاعدة البيانات لسه ما كانش موجود وقت ما جربت تدخل المبالغ (قبل ما تشغّل الـ SQL بتاعه)، فالحفظ كان بيفشل بهدوء. **بعد ما تشغّل SQL البند اللي فات، ادخل على كل إقرار متأخر تاني وحدد قيمته من زرار "السداد"، والكارت هيتحدث فورًا.**

### 23) مبالغ الإقرارات + فلتر الحالة
- السبب الحقيقي إن الكارت كان بيحسب بس الإقرارات اللي حالتها "متأخر" فعليًا (فات معادها)، فلو دخّلت مبلغ على إقرار لسه "قيد الانتظار" (زي إقرار الشهر الحالي) الكارت مكنش بيحسبه. **اتصلح**: الكارت دلوقتي بيجمع أي مبلغ متبقي على أي إقرار غير مكتمل (متأخر أو قيد الانتظار)، فهيظهر فورًا أول ما تحدد قيمة أي إقرار.
- بقى فيه فلتر "الحالة" في صفحة الإقرارات (قيد الانتظار / متأخر / مكتمل / الكل).

### 24) لوحة التحكم: كل كارت قابل للضغط + كارت مبالغ الإقرارات المتأخرة
- بقى فيه كارت جديد في لوحة التحكم اسمه "مبالغ إقرارات متأخرة" بيعرض إجمالي أي فلوس مستحقة على أي إقرار.
- **كل** الكروت في لوحة التحكم (عدد العملاء، الفواتير، المحصّل، المعلّق، المصروفات، الإقرارات المتأخرة، مبالغها) بقت قابلة للضغط — دوس على أي كارت يفتحلك جدول بالتفاصيل اللي وراه (الأسماء، المبالغ، التواريخ...).
- جدول "مبالغ إقرارات متأخرة" (سواء من لوحة التحكم أو من صفحة الإقرارات) بقى فيه 3 أعمدة: **مبلغ الإقرار**، **المدفوع**، و**المتبقي**.

### 25) تعديل الفواتير (المدير والأدمن بس)
بقى فيه زرار تعديل (✏️) جنب كل فاتورة، يظهر ويشتغل للمدير والأدمن بس — حتى على مستوى قاعدة البيانات نفسها، مش بس في الواجهة.
⚠️ **لازم SQL جديد**: شغّل `supabase/add_invoice_edit_permission.sql`.

### 26) تعليم كل الإقرارات المفلترة كمكتملة دفعة واحدة
في صفحة الإقرارات، بعد ما تفلتر بأي شكل (عميل، نوع، شهر...)، بقى فيه زرار "علّم الكل كمكتمل" بيعلّم كل الإقرارات الظاهرة في النتيجة المفلترة كمكتملة في ضغطة واحدة.

### 27) رفع شعار المكتب من داخل الموقع (من غير GitHub)
في صفحة الإعدادات، تحت بيانات المكتب، بقى فيه زرار "رفع شعار" — ترفع صورة من جهازك مباشرة وتظهر تلقائيًا في صفحة تسجيل الدخول. الحد الأقصى 400KB للصورة.

### 28) صفحة تسجيل الدخول: تصميم جديد بالكامل
- الصفحة بقت "صفحة عامة" فيها النص التعريفي عن المكتب بعرض الصفحة كاملة — تقدر تطلب مني أضيف عليها أي معلومات تانية حابب إنها تظهر لأي زائر.
- نموذج تسجيل الدخول (اسم المستخدم وكلمة السر) بقى صغير جدًا ومكانه ثابت فوق على الشمال، مخصص لموظفي المكتب بس.

### 29) فلاتر داخل كروت لوحة التحكم
دلوقتي لما تدوس على أي كارت في لوحة التحكم، الجدول اللي يفتحلك فيه فلاتر إضافية فوقه (زي: فلتر بالعميل، بالحالة، بالتصنيف... حسب نوع الكارت) تقدر تستخدمها لتضييق النتيجة أكتر.

### 30) إصلاح مهم: مشكلة دخول المتدرب (والمحاسبين)
اكتشفنا إن النظام كان بيوجّه **أي حد** بعد تسجيل الدخول لصفحة "لوحة التحكم" تلقائيًا — حتى لو دوره (محاسب أو متدرب) مالوش صلاحية يشوف الصفحة دي أصلاً! ده كان بيسبب حالة غريبة/فاضية بعد الدخول تحس إنها "مش شغالة". **اتصلح**: كل دور بيتوجّه دلوقتي لأول صفحة يقدر يشوفها فعليًا (المدير والأدمن → لوحة التحكم، المحاسب والمتدرب → العملاء)، وكمان أضفنا حماية تلقائية لو حد حاول يدخل صفحة مالوش صلاحية ليها من رابط مباشر.

### 31) كشف التكرار عند استيراد شيت العملاء
لما تستورد ملف عملاء، لو لقى اسم أو رقم ضريبي أو رقم قومي متطابق مع عميل موجود بالفعل، هيوقف ويوريك جدول بكل الصفوف المكررة (مين هو ومين اللي مكرر معاه وسبب التكرار)، وتقدر تحدد لكل صف مكرر لوحده هل تضيفه رغم التكرار أو تتجاهله، والباقي (غير المكرر) بيتضاف تلقائيًا.

## ملاحظات مهمة

- **النسخ الاحتياطي**: زي ما اتفقنا، أنت هتحمّل نسخة يدويًا بين فترة وأخرى. أسهل طريقة: من Supabase Dashboard > Database > Backups (فيه نسخ تلقائية جزء منها مجاني على الخطة الأساسية وتقدر تزود المدة بخطة مدفوعة)، أو تصدير بيانات العملاء بزرار "تصدير Excel" الموجود في صفحة العملاء بشكل دوري.
- **الأمان**: كلمات مرور المستخدمين الثمانية بقت مُدارة ومشفّرة بالكامل داخل Supabase Auth (مش زي النسخة التجريبية الأولى). لسه غيّرها من الافتراضي.
- **المرفقات**: بيانات المرفقات (صور/PDF) بتتخزن كنص base64 داخل جدول `clients` نفسه، وده يشتغل كويس للملفات الصغيرة (تحت 3MB)، لكن لو حجم مرفقات العملاء زاد كتير مستقبلًا الأفضل ننقلها لـ Supabase Storage (تخزين ملفات حقيقي) — تقدر تطلب مني ده كخطوة تانية.
- **تعديل التصنيفات وأنواع الإقرارات**: تصنيفات المصروفات قابلة للتعديل من صفحة الإعدادات مباشرة. قواعد حساب الإقرارات نفسها (المواعيد النهائية) مكتوبة في `lib/helpers.js` — لو قانون الضرائب اتغيّر تحتاج تعديل هناك.
